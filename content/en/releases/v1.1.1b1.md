## Native output previews

Yuki `1.1.1b1` adds native runner support to `/remote-export`. Previously, output
files could appear in the results list while their previews returned `NOTFOUND`:
the route only handled SSH-based runners. It now serves files directly from the
native workflow's `stageout` directory, including repeated-task paths such as
`stageout/2/plots/fit.png`, without first copying them into Yuki Storage.

The route supports MIME detection, HEAD requests, and HTTP byte ranges for file
viewers. It blocks path traversal and symlinks escaping stageout, and preserves
SSH/IHEP streaming. The related route suite passes all 17 tests.

## Previewing through Remote SSH

The companion VS Code extension fix routes image, PDF, and text previews through
an extension-host proxy and a VS Code forwarded address. This lets the local
Webview reach Yuki on the remote server. Image enlargement uses the same address,
and failed image loads show a message.

Both fixes are needed for direct native previews through Remote SSH: update the
Yuki server code and reload its HTTP service, then install the extension build
containing the forwarding fix. See the [VS Code guide](/guide/3_celebi_extension_vscode/).

## Prerelease status

This is a Yuki beta patch; CelebiChrono remains at `1.1.0`. The source version and
release notes are prepared. This website update does not announce a PyPI or
Marketplace publication. Validation on the target Remote SSH deployment is still
pending. Previewing a file does not collect or archive it; use `collect` when you
want a retained copy in Yuki Storage.
