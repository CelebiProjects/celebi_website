# Using the Celebi VS Code Extension

In the previous tutorials, we learned how to create Celebi workflows, connect multiple tasks, and execute analysis code on a remote server.

However, using the command-line interface alone makes it less convenient to inspect task details and examine output files, especially when dealing with large datasets stored remotely.

To address this, we provide the **Celebi extension for Visual Studio Code (VS Code)**. It offers a graphical interface for managing workflows, inspecting task dependencies, monitoring execution status, and previewing analysis results.

Most importantly, **you can preview intermediate results directly in VS Code without downloading entire output files to your local computer.**

## 1. Install the Celebi Extension

Open VS Code and navigate to the **Extensions** panel (`Ctrl+Shift+X`).

Search for `Celebi` and install the extension.

![Celebi extension in VS Code](https://github.com/user-attachments/assets/e2fc41d0-8431-4c79-894f-d98539e29057)

After installation, a Celebi icon will appear in the Activity Bar on the left side of VS Code.

## 2. Explore the Celebi Panel

Click the Celebi icon to open the extension panel.

![Celebi extension overview](https://github.com/user-attachments/assets/87092320-57a8-47aa-a54f-c95f0400837f)

The panel displays the structure of your Celebi project, including its directories and tasks.

You can expand directories and select individual tasks to navigate through your analysis workflow without manually locating their files.

### Connect to Celebi

Make sure Yuki and Celebi have been started as described in the first tutorial.

Then click the **Refresh** button in the upper-right corner of the Celebi panel.

Once the connection is established, the DITE status should display:

```text
DITE: connected
```

This indicates that celebi is working.

## 3. Inspect Task Details

Select a task in the Celebi panel to open its details on the right.

![Celebi task details](https://github.com/user-attachments/assets/4271ab4d-3d75-416b-96c2-d1b23b50c2fa)

The task details view contains several sections.

### 3.1 README

The `README.md` file describes the purpose and functionality of the task.

It is strongly recommended to **write a README for every task**, especially in large workflows with many processing steps.

A clear README helps you and other collaborators understand what each task does without having to inspect its source code.

### 3.2 Job Status

The **JOB STATUS** section provides information about the task's execution, including its current status and requested runner.

This allows you to check the progress of your analysis directly from VS Code.

### 3.3 Predecessors and Successors

The **PREDECESSORS** section lists the upstream tasks that provide input data to the current task.

The **SUCCESSORS** section lists downstream tasks that depend on its output.

You can click the corresponding navigation icons to jump directly to related tasks.

These sections are particularly useful for understanding complex workflows structured as directed acyclic graphs (DAGs).

### 3.4 Task Configuration

The **CELEBI.YAML** section allows you to inspect and edit the task configuration, including:

- Execution commands
- Conda environment
- Memory limit
- Other task settings

This provides a convenient alternative to locating and editing the configuration file manually.

## 4. Preview Analysis Results

The **RESULTS** section is one of the most useful features of the extension.

It allows you to browse and preview output files generated by your analysis tasks without manually transferring them from the remote server.

### 4.1 Preview ROOT files

Click a ROOT file in the RESULTS section.

The extension displays its contents, allowing you to explore objects such as TTrees.

![ROOT file browser](https://github.com/user-attachments/assets/94bb3e92-7be2-43f1-9027-6461d243a442)

For example, click `DecayTree` to expand the tree and browse its branches.

Select a variable, and its distribution will appear in the preview panel after a short loading time.

![ROOT variable distribution](https://github.com/user-attachments/assets/0a27ff88-1fe4-462d-b39d-de6af98b59fa)

This is particularly useful for quickly checking:

- Kinematic distributions
- Mass spectra
- Selection results
- Intermediate analysis outputs

You can inspect these distributions without writing additional plotting scripts or downloading the entire ROOT file.

### 4.2 Preview PDF files

The extension also supports previewing PDF output files, such as fit results and diagnostic plots.


![PDF preview in Celebi](https://github.com/user-attachments/assets/3b7e3a0a-f3bc-4485-a352-13c5b92bc120)

To view the PDF in a larger window, click on the figure directly.

![Expanded PDF preview](https://github.com/user-attachments/assets/4d0f9294-335b-433e-a3b3-c0e94258d9fa)

This makes it convenient to inspect fitting results, compare distributions, and check analysis quality directly within VS Code.

### 4.3 Download output files

If you need to perform additional local processing or retain a copy of an output file, you can download it using the extension's file actions.

For large intermediate datasets, however, it is generally preferable to keep the files on the remote server and use the preview functionality whenever possible.

## 5. Summary

The Celebi VS Code extension provides a convenient graphical interface for working with Celebi analysis projects.

Its main features include:

- **Workflow navigation:** Browse directories, tasks, and their dependencies.
- **Task inspection:** View execution status, configurations, and documentation.
- **Remote result preview:** Explore ROOT files and visualize variable distributions without downloading entire datasets.
- **Plot inspection:** Preview PDF figures and analysis results directly in VS Code.
- **On-demand downloads:** Download output files only when necessary.

Together with the Celebi command-line interface, the extension provides a more efficient way to develop and manage complex physics analyses.

**With Celebi, you can focus on developing analysis code locally while keeping large datasets and intermediate results on the remote server, previewing them whenever needed.**
