## 命令与帮助

- 三个入口现在各司其职：`celebi` 进入交互式 shell，`celebi-cli` 提供完整的
  非交互命令行，`celebi-git` 专门处理 Git 操作。
- 命令仍保持扁平结构，但按项目、导航、对象、配置、执行、数据、runner、检查、
  文件与维护等任务分类显示。
- 规范命令名更加明确，包括 `project-path`、`set-parameter`、
  `set-environment`、`set-memory-limit`、`runner-environments` 和 `view-url`。
  旧拼写仍作为隐藏兼容别名保留。
- 交互式 shell 完整支持 `helpme`、`help <command>` 和
  `<command> --help` 三种帮助形式。
- CLI 补齐了此前缺失的批量输入/对象、缓存设置、结果检查、文档辅助、文件显示与
  导出、impression 维护和 bookkeeping 等命令。
- 移除无实际实现的 `jobs`；工作流检查请使用 `status`、`history` 和
  `engine-logs`。

## 提交与实时状态

- `submit` 同时负责首次执行和安全重提：活动工作流会去重，已完成结果会复用，
  failed、dissonant 或 stopped 工作流可被替换，并记录前序工作流信息。
- `submit --with-unknown` 会先刷新不确定的 SSH 启动状态，只有确认失败后才创建
  替代工作流。
- `status --wait` 与 Yuki 的工作流刷新锁同步，查询 runner，并持续输出发生变化的
  状态快照，直到对象进入终态。`--poll-interval` / `-i` 可调整刷新间隔。
- 导航与项目命令在 Celebi 项目之外会清晰报错，不再抛出内部异常。

## Yuki runner 与可靠性

- 新增 IHEP HepJob 后端：工作流协调器和各条 Snakemake 规则均通过 `hep_sub`
  提交；支持子任务跟踪与取消、Celebi 内存限制映射，并把运行状态放在共享存储上。
- SSH 启动标记延迟时保持 `unknown` 且可继续轮询，直到后续证据确认成功或失败。
- failed/stopped 远端工作流会被阻止重新发布陈旧缓存；完成的缓存项采用原子方式发布。
- 依赖失败会保存结构化 `blocked_by` 快照；失败工作流的 stageout 可显式收集为
  非正式诊断输出。
- Yuki 按职责重组为 jobs、workflows、runners、execution、storage、services 与
  utils 等模块。
- 基于 Conda 的 RabbitMQ 安装更可靠，并启用与 Celery 兼容的运行方式。
